## 一、接入总览

接入分三步，全部完成后子项目即可在工作台中嵌入浏览：

1. **注册**：在 `apps.json` 注册表中登记你的子项目（id / name / url / icon / description）。
2. **布局**：注册后自动出现在工作台的侧边栏导航、接入项目列表、项目一览卡与详情面板。
3. **适配嵌入**：按本文档约定，让你的子项目检测嵌入参数、隐藏自身导航，并（可选）与主站通信。

接入原则：

- **渐进式接入**：未做任何改造的子项目也能被嵌入渲染，只是自身导航不隐藏；适配到什么程度，嵌入效果就到什么程度。
- **子项目自选**：选择「共享工作台登录」或「自建登录」，二者不冲突，详见下一节。
- 主站只做一件事：点击子项目后在核心区用 iframe 渲染 `<子项目URL>?embed=1`，其余交给子项目自己。

## 二、两种接入模式

| | 接入模式（共享登录） | 不接入模式（自建登录） |
|---|---|---|
| 登录方式 | 子项目未登录 → 跳主站登录页 → 登录后回跳 | 子项目自建登录模块，工作台不干预 |
| 适用场景 | 私有/自有服务，希望复用主站账号体系、处处免登 | 已具备独立账号体系、或对外公开无需登录的服务 |
| 需要改造 | 检测 `embed=1`、跳转主站登录、postMessage、`SameSite=None` Cookie（跨域期） | 只需检测 `embed=1` 隐藏自身导航 |
| 成本 | 较高，但一劳永逸（统一鉴权迁移后免二次登录） | 低，保持现状 |

取舍建议：

- 若子项目面向自己或受信任用户、且不想维护多套账号 → 选**接入模式**。
- 若子项目已有账号体系、或需要向公众匿名展示 → 选**不接入模式**；用户嵌入浏览时在 iframe 内自行登录即可。

两种模式对「注册」「布局」「嵌入模式改造」的要求相同，仅「登录」环节不同。

## 三、注册

在主站仓库根目录的 `apps.json` 中登记。结构为 `{ "注册键": { 字段… } }`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id`（注册键） | string | ✓ | `apps.json` 顶层键，全局唯一；侧边栏/列表/详情均以它定位 |
| `name` | string | ✓ | 显示名称，用于侧边栏、卡片、详情面板与嵌入标题 |
| `url` | string | ✓ | 子项目地址，须为 `https://…`；`/` 保留给工作台本体（`workbench`），不可被嵌入 |
| `icon` | string | 建议 | 图标语义：`home`（工作台/首页）、`switch`（代理/切换）、`sub`（订阅/管理）；未识别值回退默认图标 |
| `description` | string | 建议 | 简述，展示在卡片与详情面板 |

当前注册表（节选自 `apps.json`）：

| id | name | url | icon | description |
|---|---|---|---|---|
| `workbench` | 个人工作台 | `/` | `home` | Calpher 个人工作台首页 |
| `socks` | 代理切换台 | `https://socks.kypher.kdns.fr` | `switch` | Free Residential IP Proxy Controller |
| `calpher-sub` | 订阅管理 | `https://submgr.kypher.ccwu.cc` | `sub` | 多用户 Clash/V2Ray 订阅编排与分发 |

约束：

- `url` 必须是 `https://`。`http` 无法嵌入（浏览器会拦截混合内容）。
- `url` 对应页面必须**允许被 iframe 加载**：不要对该页面设置 `X-Frame-Options: DENY` / `SAMEORIGIN`，也不要通过 CSP `frame-ancestors 'none'` 禁止嵌套（登录页等敏感页除外——嵌入登录页本就没有意义）。
- 保留 `workbench`（`url: "/"`）与根路径 `"/"`：工作台本体不参与嵌入，点击它回到本地视图。
- 注册后，该 `url` 的 hostname 会自动进入主站登录跳转白名单（见第八节）。

## 四、布局

注册成功后，子项目出现在工作台的四处：

- **侧边栏导航**（`#primaryNav`）：点击 → 进入嵌入视图。
- **接入项目列表**（`#projectList`）：带「打开」入口，点击 → 进入嵌入视图。
- **项目一览卡**（`#projectGrid`）：整卡点击 → 进入嵌入视图。
- **详情面板**（`#detailsPanel`）：「打开项目」按钮 → 进入嵌入视图。

进入嵌入视图后的行为：

- 主站核心区加载 iframe：`<子项目URL>?embed=1`（子项目 URL 已有查询参数时自动改为 `&embed=1`）。该参数由主站自动追加，子项目只需响应它。
- 侧边栏与顶栏保留在主站侧，由主站渲染，子项目无需关心。
- 顶栏出现返回按钮（`#backBtn`），点击回到本地视图；点击侧边栏「个人工作台」同样回到本地视图。
- 嵌入条始终提供「在新窗口打开」（`#embedOpen`）逃生链接，指向子项目原地址，任何情况下可用。
- 顶栏主标题默认显示注册表 `name`，收到子项目 `title` 消息后更新。

**移动端（≤1180px）行为**：

移动端 iframe 空间有限、交互受限，工作台改为直接新开标签页打开子项目，并在 URL 中追加 `?from=workbench`（或 `&from=workbench`）参数。子项目检测此参数后，应在页面显著位置渲染一个「返回工作台」按钮，让用户能一键跳回工作台。

> 两个参数互斥：`embed=1` 表示 iframe 嵌入（桌面端），`from=workbench` 表示移动端来源跳转。子项目可按此区分展示逻辑。

## 五、嵌入模式改造

子项目需要知道「我正在被嵌入」，并在该状态下隐藏自己的导航外壳、只渲染内容主区域。

约定：检测到嵌入参数后，在 `<body>` 上打标记 `data-embed`，样式一律挂在 `body[data-embed]` 选择器下。主站没有预设任何子项目内部类名，请以自身 HTML 结构为准。

示例——页面初始化时检测两个参数（`embed=1` 桌面端嵌入 / `from=workbench` 移动端跳转）：

```html
<script>
  const _qp = new URLSearchParams(location.search);
  if (_qp.get('embed') === '1') {
    // 桌面端：被 iframe 嵌入，隐藏自身导航外壳
    document.body.dataset.embed = '1';
  } else if (_qp.get('from') === 'workbench') {
    // 移动端：从工作台新开页面跳转过来，显示「返回工作台」按钮
    document.body.dataset.fromWorkbench = '1';
  }
</script>
```

**移动端「返回工作台」按钮**（当 `body[data-from-workbench]` 时渲染）：

```css
/* 默认隐藏，检测到 from=workbench 时显示 */
.workbench-back-btn { display: none; }
body[data-from-workbench] .workbench-back-btn { display: flex; }
```

```html
<!-- 放在页面顶部或固定悬浮位置 -->
<a class="workbench-back-btn" href="https://www.kypher72.indevs.in" target="_blank" rel="noopener">
  ← 返回工作台
</a>
```

> 返回入口应与工作台视觉基线一致；默认使用 ocean 蓝作为链接/主操作色，emerald 绿作为成功态或辅助强调色。

示例——隐藏自身外壳、保留内容区（桌面端嵌入模式）：

```css
/* 隐藏自身顶栏 / 侧边栏 / 页脚 / 凭据展示 */
body[data-embed] .site-header,
body[data-embed] .site-nav,
body[data-embed] .site-footer,
body[data-embed] .credential-box {
  display: none !important;
}
/* 内容主区域撑满可视区 */
body[data-embed] main {
  margin: 0;
  padding: 0;
  max-width: none;
}
```

注意事项：

- 不要做 **frame-busting**（如 `if (window.top !== window) { window.top.location = location; }`），这会破坏嵌入。
- 不要依赖 `window.top` 与主站共享 DOM/CSS——不同源，iframe 是隔离的。
- 登录态判断请使用自己的会话（见第六节），不要读取主站 DOM。

## 六、会话 Cookie

主站会话 Cookie：`calpher_auth`，`Domain=kypher72.indevs.in; Path=/; HttpOnly; Secure; SameSite=Lax`（有效期 30 天）。

现状（子项目与主站异域）：

- `socks.kypher.kdns.fr`、`submgr.kypher.ccwu.cc` 与 `www.kypher72.indevs.in` **不同站点**（不同 registrable domain）。
- 因此主站的父域 Cookie **不会**随子项目的请求发出；子项目也读不到主站的 `calpher_auth`。
- 子项目自己的会话 Cookie 在被嵌入的跨域 iframe 中是**第三方 Cookie**，默认被现代浏览器拦截（Chrome/Edge 默认、Firefox 严格模式、Safari ITP），**必须显式设置 `SameSite=None; Secure`** 才会随 iframe 内请求发出：
  - `Set-Cookie: <your_session>=…; Path=/; HttpOnly; Secure; SameSite=None`
- 第三方 Cookie 依赖用户对站点的信任：部分浏览器在未手动允许站点时仍会拦截第三方 Cookie，此时 iframe 内呈现「未登录」，用户需在该站点的独立标签页完成登录后刷新。请勿在接入模式下对未登录做死循环跳转。

长期方案（统一鉴权迁移后，见第九节）：

- 子项目迁移到 `kypher72.indevs.in` 父域下的子域名（如 `<app>.kypher72.indevs.in`）后，嵌入的 iframe 变为**同站（same-site）**，父域 `calpher_auth` Cookie 自动随请求发出，子项目不再需要 `SameSite=None`，登录态在嵌入中直接可用。
- “同站”不要求 hostname 完全相同：`www.kypher72.indevs.in`、`socks.kypher72.indevs.in`、`submgr.kypher72.indevs.in` 可以保持不同 origin，但都处于 `kypher72.indevs.in` 这个 Cookie 父域下。当前 `socks.kypher.kdns.fr` 和 `submgr.kypher.ccwu.cc` 不满足该条件。

## 七、postMessage 协议

子项目通过 `postMessage` 与主站通信。所有消息体必须带 `source: 'kypher-embed'`。

子项目 → 主站的消息：

| type | 载荷 | 主站行为 |
|---|---|---|
| `ready` | 无 | 隐藏「正在加载子项目…」加载态 |
| `title` | `title: string` | 更新顶栏主标题与嵌入条标题（默认取注册表 `name`） |
| `exit` | 无 | 请求退出嵌入，回到本地工作台视图 |

发送示例（子项目侧）：

```js
// targetOrigin 必须是主站 origin，绝不要用 '*'
window.parent.postMessage({ source: 'kypher-embed', type: 'ready' }, 'https://www.kypher72.indevs.in');
window.parent.postMessage({ source: 'kypher-embed', type: 'title', title: '代理切换台' }, 'https://www.kypher72.indevs.in');
window.parent.postMessage({ source: 'kypher-embed', type: 'exit' }, 'https://www.kypher72.indevs.in');
```

主站侧校验（双向 origin 校验，其一）：

- 仅接受 `event.source === iframe.contentWindow`（必须是当前嵌入 iframe 的 window）。
- 仅接受 `event.origin` **精确等于** 该子项目注册 `url` 的 origin（例如 `https://socks.kypher.kdns.fr`）。
- 以上任一不满足，消息被忽略。

主站白名单说明：主站不做额外白名单，校验的 origin 直接取自 `apps.json` 中该项目的 `url`。因此**未注册的域名永远无法成为合法来源**；新项目注册后其 origin 自动生效，无需改代码。

子项目侧校验（双向 origin 校验，其二，务必加上）：

```js
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://www.kypher72.indevs.in') return; // 只信任主站
  const d = event.data;
  if (!d || d.source !== 'kypher-embed') return;
  // 当前主站不会主动发送消息；此校验为未来主站 → 子项目消息预留，并防御任意来源消息。
});
```

补充说明：

- 主站加载态由 iframe 的 `load` 事件或 `ready` 消息先到先得地隐藏；若子项目未适配，仅 `load` 事件生效。
- 主站不读取 iframe 内部状态；子项目未登录由子项目自行处理（见第八节），主站只提供「在新窗口打开」逃生。

## 八、登录跳转（接入模式）

仅「接入模式」的子项目需要。目的：子项目未登录时，借用主站登录页完成登录，登录后回跳子站。

接入流程：

1. 子项目检测到自身未登录 → 跳转主站登录页：
   ```
   https://www.kypher72.indevs.in/login?redirect=<子站URL>
   ```
   其中 `<子站URL>` 须先 `encodeURIComponent`。示例：
   ```
   https://www.kypher72.indevs.in/login?redirect=https%3A%2F%2Fsocks.kypher.kdns.fr
   ```
2. 用户在主站登录页输入账号密码，主站校验成功。
3. 主站返回 `Set-Cookie: calpher_auth`（父域 Cookie，见第六节）。
4. 主站校验 `redirect` 是否合法（见下），合法则跳回该地址，非法则回退 `/`。
5. 子站校验自身会话：同父域（迁移后）直接放行；异域（现状）由子站按自身会话机制处理（token 换发为长期工作，本期不实现）。

开放重定向防护规则：

- `redirect` 合法条件二选一：
  1. 与主站同 origin 的站内路径（如 `/`、`/xxx`）；
  2. `https://` 且其 **hostname（不含端口）** 在注册表白名单中。白名单 = `apps.json` 中所有非 `/` 的 `http(s)` 子项目 `url` 的 hostname。
- 其余一律拒绝并回退 `/`：非注册域名、`http`、`javascript:`、协议相对地址等均不合法。
- 白名单由主站 `worker.js` 在渲染 `/login` 时从 `apps.json` 动态注入 `login.html`（占位符 `__REDIRECT_ALLOWLIST__` 替换），**非前端硬编码**。

当前白名单（随注册表自动生成）：

```
socks.kypher.kdns.fr
submgr.kypher.ccwu.cc
```

## 九、统一鉴权（长期目标）

现状下，异域子项目各自维护会话、依赖 `SameSite=None`，登录体验割裂。长期目标：

1. **迁父域**：把子项目迁移到 `kypher72.indevs.in` 下的子域名（如 `<app>.kypher72.indevs.in`）。
2. **复用 `auth/auth.js`**：子项目复用本仓库的 `auth/auth.js`（同一套 HMAC 签名与验证逻辑、同一个签名密钥、同一个 `calpher_auth` Cookie，`Domain=kypher72.indevs.in`）。
3. **一处登录，处处免登**：在任意一个子域名登录后，父域 Cookie 即对所有子域名生效；被嵌入的 iframe 同站携带 Cookie，无需 `SameSite=None`、无需 token 换发。
4. **共享登录入口**：`/login` 页面与 `?redirect=` 参数即全平台统一登录入口。

> 仅迁移 DNS/自定义域名还不等于完成统一鉴权。父域负责让浏览器携带 Cookie；共享 Cookie 名、签名密钥和验证代码负责让每个子项目能正确识别该会话。

本期不落地该迁移；迁移完成前，异域约束（第六节）与登录跳转协议（第八节）仍然适用。
