# Calpher Workbench 子项目创建与接入标准

> 本文是后续 Calpher 子项目创建、改造和接入的权威标准。主站：`https://www.kypher72.indevs.in`。

## 1. 不可变原则

1. 子项目始终是可独立部署、独立访问、独立维护的完整网站。
2. **同时提供主站地址与该子站的独立密钥时启用统一鉴权；缺少任一项时保持独立站。**
3. 接入不能改变业务 API、机器接口、公开订阅或 Agent 的既有鉴权语义。
4. 前端结构按 `octopus-kaogong-workbench` 重做，不是只替换颜色。
5. 主站仓库的 `design-system/` 与 `auth/auth.js` 是母版；子项目保存本地拷贝，不在运行时跨域依赖主站静态资源。
6. `apps.json` 保存管理员维护的全局项目；成员和管理员自行添加的个人接入项目、网站导航保存在 `WORKBENCH_KV`。
7. 全局或个人项目的注册名称只用于主站导航，不得覆盖子项目自己的产品名、HTML 标题或独立站品牌。
8. 网站导航只是个人导航，绝不进入 handoff 白名单，也不共享登录。

## 2. 两种运行模式

| | 统一鉴权模式 | 独立站模式 |
|---|---|---|
| 触发条件 | `AUTH_MASTER_ORIGIN` 与 `AUTH_COOKIE_SECRET` 均存在 | 缺少任意一项 |
| 网页登录 | 主站统一登录，签名 handoff 回子站 | 使用项目原有登录 |
| 本地账号 | 不要求子站配置主站账号 | 完整保留 |
| 页面外壳 | 主站桌面端可嵌入；移动端进入子站完整页面 | 仅显示子项目自己的完整页面，不显示主站侧栏 |
| 主站不可用 | 已签发会话在有效期内仍可验证 | 完全不受影响 |
| 适用 | Calpher 自有子项目 | 单独交付、公开部署、第三方自管 |

标准配置：

```toml
[vars]
AUTH_MASTER_ORIGIN = "https://www.kypher72.indevs.in"
PARENT_DOMAIN = "kypher72.indevs.in" # 可选，同父域部署时使用
```

```bash
npx wrangler secret put AUTH_COOKIE_SECRET
```

每个子站都使用自己的 `AUTH_COOKIE_SECRET`，包括 `apps.json` 注册的平台子站和用户创建的个人子站。主站为每个接入生成独立密钥，并仅用该密钥为对应 origin 签发 handoff；子站把管理页中显示的同一值配置为自己的 Cloudflare Secret。主站自身的 `AUTH_COOKIE_SECRET` 只用于主站会话与成员密码保险箱，不与任何子站共享。不要把任何密钥写入 git、`wrangler.toml` 或前端代码。不要新增 `AUTH_MASTER_TOKEN` 作为基础接入条件。

主站也配置 `AUTH_MASTER_ORIGIN` 为自己的公开 origin，并另外保存网页登录所需的 `AUTH_MASTER_NAME`（账号名，未配置时默认 `admin`）与 `AUTH_MASTER_PASS`。管理员账号密码保持 Cloudflare 环境变量中的明文值，不进入 KV，也不在应用层加密。这两个登录凭据只属于主站，统一鉴权子项目不配置。`AUTH_MASTER_TOKEN` 与旧 `/api/auth/sync` 协议已废弃，不属于当前接入标准。

主站必须绑定：

```toml
[[kv_namespaces]]
binding = "WORKBENCH_KV"
id = "<Cloudflare KV namespace id>"
```

普通成员、成员密码摘要、加密密码保险箱、配额、个人接入子站和网站导航保存在该 KV。普通成员密码同时保存带随机盐的 `PBKDF2-SHA256` 登录摘要，以及使用主站 `AUTH_COOKIE_SECRET` 派生密钥加密的 AES-GCM 密文。成员列表接口绝不返回密码；只有管理员专用、禁止缓存的密码查看接口可按需解密。管理员密码仍只保存在 Cloudflare 环境变量中。

模式判定必须等价于：

```js
const federated = Boolean(
  normalizeOrigin(env.AUTH_MASTER_ORIGIN)
  && String(env.AUTH_COOKIE_SECRET || '').trim()
);
```

只配置一个变量时必须降级为独立站并记录配置警告，不能进入半接入状态。

## 3. 新项目目录基线

```text
child-project/
├── auth/
│   └── auth.js             # 从主站复制的权威鉴权模块
├── design-system/
│   ├── styles.css          # 从主站复制并按业务组合
│   └── components.js
├── src/ 或 worker.js
├── wrangler.toml
└── README.md               # 写明独立/统一鉴权的配置方式
```

允许适配项目技术栈调整路径。子项目可只保留验会话、验 handoff、写 Cookie 和构造主站登录地址所需的函数，但票据格式、Cookie 名、模式判定、安全校验与属性规则必须和母版一致。

## 4. 项目注册与个人导航

### 4.1 管理员全局项目

在主站 `apps.json` 增加：

```json
{
  "project-id": {
    "name": "项目名称",
    "url": "https://project.example.com",
    "icon": "switch",
    "description": "一句话业务说明"
  }
}
```

要求：

- key 是稳定、全局唯一的项目 id。
- `name` 只用于主站侧栏、项目列表和嵌入窗口标题；子项目继续显示自身原有产品名。
- `url` 必须是 HTTPS origin 或其固定首页。
- 页面允许被主站 iframe 加载，不设置冲突的 `X-Frame-Options` 或 `frame-ancestors`。
- 注册 URL 的 **origin** 自动成为管理员全局 handoff 回跳白名单；未注册 origin 不得收到全局密钥签发的登录票据。
- 修改域名时先改注册表，再部署主站，最后切换子站。
- `apps.json` 只保存名称、URL、图标和简介；每个平台子站的独立密钥、删除状态保存在 `WORKBENCH_KV` 的 `platform-integration:<项目 id>`。
- 管理页必须单独展示这些平台接入，允许管理员查看、复制和删除该项目的独立密钥；不得计入管理员的个人接入配额。
- 管理员可为每个平台子站单独启用或关闭预加载；该运行设置保存在对应 `platform-integration:<项目 id>` KV 记录中，不要求修改或重新部署 `apps.json`。
- 删除平台接入只移除工作台入口、handoff 白名单与统一退出目标，不会删除已经部署的子站 Worker。

### 4.2 用户个人接入项目

管理员和普通成员都可在自己的工作台新增个人接入项目：

- 普通成员默认最多 3 个，管理员可调整单个成员的上限。
- 每个项目拥有独立随机密钥，不与其他成员或其他项目共享。
- 子站配置 `AUTH_MASTER_ORIGIN` 和该项目密钥后启用统一鉴权。
- 主站仅使用项目所属账号的密钥给该项目 origin 签票。
- 管理员代看成员工作台时，以成员身份签发其项目票据；目标 URL 携带 `calpher_owner=<成员名>`，用于登录回跳时恢复工作台上下文。
- 项目删除后立即从该账号的 handoff 白名单和统一退出目标中移除。
- 管理页显示和计算的个人接入用量只包含当前账号保存在 `WORKBENCH_KV` 的项目，不包含 `apps.json` 中的平台接入。

### 4.3 网站导航

管理员和普通成员都可添加普通 HTTPS 网站导航：

- 普通成员默认最多 10 个，管理员可调整单个成员的上限。
- 网站导航支持创建、编辑和删除，可配置侧边栏名称、URL、图标、简介与可选详情。
- 网站导航作为当前账号的独立收藏区域展示；桌面端和移动端都直接新开标签页或窗口，不进入主站嵌入窗口，避免普通网站缺少返回工作台入口。
- 网站导航不生成密钥，不进入 `/api/auth/handoff` 或 `/api/auth/embed-handoff` 白名单。
- 个人接入项目可选 `preload` 加载策略。启用后主站工作台会在桌面端空闲时后台预热最多 3 个子站 iframe，切换时复用已完成初始化的页面实例；未启用时保持按需加载。移动端、省流量模式和页面不可见时跳过预热。网站导航不支持该字段。
- 目标网站只需具备常规响应式页面，不要求实现 Calpher 鉴权、嵌入、主题或返回工作台协议。
- 接入子站的简介用于列表摘要，详情用于右侧详情区域；未填写详情时默认收起且不显示空的展开入口，填写详情后窗口模式默认收起并提供右侧按钮随时展开。网站导航的简介和详情只用于工作台收藏信息展示。

### 4.4 成员与管理权限

- 管理员由 `AUTH_MASTER_NAME`、`AUTH_MASTER_PASS` 定义。
- 普通成员由管理员创建并保存在 `WORKBENCH_KV`，默认接入上限 3、网站导航上限 10。
- 管理员可调整成员两类配额、停用成员、删除成员及其工作台数据。
- 管理员可查看和管理成员工作台；普通成员只能访问自己的数据。
- 管理员可按需查看普通成员密码；默认界面保持遮罩，明文只通过专用接口即时返回且禁止缓存。
- 普通成员可修改自己的用户名和密码。修改用户名时必须同步迁移该成员的工作台记录并重新签发主站会话。
- 普通成员可删除自己的账号；管理员删除成员或成员自删时，必须同时删除成员资料、个人接入子站和网站导航。
- 所有子站、网站导航、成员和账号删除操作都必须二次确认。
- 停用成员后，其现有主站会话在下一次请求时失效。

## 5. 统一鉴权协议

### 5.1 会话

- Cookie 名：`calpher_auth`
- 格式：`base64url(JSON).base64url(HMAC-SHA256)`
- payload：`v`、`typ=session`、`sub`、`role`、`iat`、`exp`
- 默认有效期：30 天
- 同父域属性：`Path=/; HttpOnly; Secure; SameSite=Lax; Domain=<PARENT_DOMAIN>`
- 异域独立访问属性：host-only、`SameSite=None; Secure`
- 异域 iframe 属性：host-only、`SameSite=None; Secure; Partitioned`
- 仅当当前 hostname 属于 `PARENT_DOMAIN` 时添加 `Domain=<PARENT_DOMAIN>`；`Partitioned` Cookie 不得设置 `Domain`。

每次验证必须检查 HMAC、版本、类型与过期时间。生产环境未配置 `AUTH_COOKIE_SECRET` 时不得使用公开默认密钥。

浏览器在密钥轮换、普通访问和 iframe 分区访问交错后，可能同时发送多个同名 `calpher_auth`。认证实现必须读取并逐个验证所有同名值，接受第一个合法且未过期的 session；不得只取 Cookie 头中的第一个值，也不得因其中一个值 URL 解码失败而放弃后续值。

### 5.2 跨域 handoff

不同 registrable domain 无法共享 Cookie，例如当前：

- 主站：`www.kypher72.indevs.in`
- Socks：`socks.kypher.kdns.fr`
- 订阅管理：`submgr.kypher.ccwu.cc`

因此统一登录必须支持：

```text
子站受保护页
  -> 主站 /login?redirect=<子站当前完整 URL>
  -> 主站无会话时登录；已有会话时自动继续，不得再次要求密码
  -> 主站 /api/auth/handoff?redirect=<目标>
  -> 子站 /.calpher/auth/callback?ticket=<短时票据>
  -> 子站写本地 calpher_auth
  -> 302 回原页面（最终 URL 不含 ticket）
```

主站桌面端嵌入异域子站时，不直接加载业务首页。主站先请求 `/api/auth/embed-handoff?redirect=<子站 URL?embed=1>`，再把返回的子站 callback URL 赋给 iframe。callback 在主站这个顶层站点的分区内写入 `Partitioned` 会话，然后跳到业务页。这样嵌入态不依赖普通第三方 Cookie。

Safari/WebKit 默认全面阻止第三方 Cookie；需要覆盖其严格隐私模式时，同一父域部署仍是无交互免登的首选。若必须长期维持异域 iframe，子项目还应实现 Storage Access API 的用户授权回退。独立标签页和移动端打开不受此 iframe 限制。

handoff payload：`v`、`typ=handoff`、`sub`、`role`、`aud`、`returnUrl`、`nonce`、`iat`、`exp`。

`nonce` 必须令每张票据唯一。基础实现不依赖中心化存储，因此票据是短时、受众绑定票据，不宣称服务端一次性消费；如果业务要求严格防重放，必须增加 KV 或 Durable Object 消费记录，并在首次回调后标记 `nonce` 已使用。

强制安全规则：

- TTL 不超过 90 秒。
- `aud` 必须精确等于接收子站 `location.origin`。
- `returnUrl.origin` 必须等于 `aud`。
- 主站只给当前账号可见的接入项目签票：管理员全局项目来自 `apps.json`，个人项目来自该账号的 KV 工作台。
- 平台项目和个人项目都使用各自独立密钥签票，任何两个项目之间都不得复用密钥。
- 网站导航不得收到票据。
- 主站 `/login?redirect=...` 检测到有效会话后必须自动进入 handoff，不能停留在登录表单。
- 回调只接受 GET，验证失败返回 `401`，不写 Cookie。
- 回调成功后立即 302，票据不留在最终 URL、日志或前端存储。
- iframe handoff 必须由已登录主站按注册 origin 即时签发，子站不得接受前端自造 audience。

### 5.3 子站路由行为

统一鉴权模式至少实现：

| 路由类型 | 未登录行为 |
|---|---|
| 页面 GET | `302` 到主站 `/login?redirect=...` |
| 浏览器 `/api/*` | `401` JSON，包含 `loginUrl` |
| `/.calpher/auth/callback` | 验票、写 Cookie、回原页 |
| 机器接口 / Agent / public URL | 维持原鉴权，不做网页登录跳转 |

前端收到统一鉴权 `401` 后必须用顶层页面跳转：

```js
if (response.status === 401 && data.loginUrl) {
  window.top.location.href = data.loginUrl;
}
```

在 iframe 中不要把主站登录页加载到 iframe 内。

### 5.4 同父域部署

同一 hostname 不是必需条件；同一 registrable parent 才能共享父域 Cookie：

```text
www.kypher72.indevs.in
socks.kypher72.indevs.in
submgr.kypher72.indevs.in
```

迁到上述结构并配置 `PARENT_DOMAIN=kypher72.indevs.in` 后，共享 Cookie 是快速路径；handoff 继续保留作为跨域及异常回退。统一鉴权不得把迁域名作为上线前置条件。

### 5.5 跨域统一退出

主站 origin 无权直接删除其他域名的 host-only Cookie。因此统一退出必须使用前通道级联，不能只清主站 Cookie：

```text
主站 GET /api/auth/logout
  -> 隐藏 iframe 访问每个子站 /api/auth/logout?partitioned=1
     清除主站顶层站点分区内的 Partitioned 会话
  -> 按当前账号可见的全局和个人接入项目顺序顶层访问每个子站
     /api/auth/logout?return=<主站下一步地址>
     清除子站普通 host-only 会话
  -> 主站 /login
```

要求：

- 主站退出入口使用顶层页面导航，不能只发一个主站 `POST` 后直接跳登录页。
- 主站会话必须保留到最后一个子站普通会话清除完成，最终回到主站时再删除；提前清除会导致后续步骤无法取得当前账号的接入项目清单。
- 子站统一鉴权模式提供 `GET /api/auth/logout`，同时支持普通 Cookie 与 `partitioned=1` 的 Partitioned Cookie 清除。
- 子站 `return` 只允许与 `AUTH_MASTER_ORIGIN` **精确同 origin**，禁止开放跳转。
- 主站只级联当前账号可见的 HTTPS 接入项目 origin，不包含网站导航。
- 所有退出响应设置 `Cache-Control: no-store`。
- 独立站模式保留原有退出接口和本地会话销毁行为，不要求跳主站。

## 6. 独立站兼容要求

未同时配置主站地址与该子站独立密钥时：

- Socks 等已有 Basic Auth 的项目继续使用 Basic Auth。
- UUID/KV 会话项目继续使用 UUID/KV 登录。
- 本地用户、角色、Bearer、API token 与 session 数据结构不要求迁移。
- 页面上不显示“主站登录”，不请求主站，不依赖 `apps.json`。
- 页面不显示 Calpher Workbench 的侧栏或返回入口，只保留子项目自己的导航与品牌。
- 删除接入变量后重新部署即可恢复独立站，不能再改代码。

统一身份映射到既有业务用户时，应使用项目已有管理员标识。例如 UUID 项目可将统一管理员映射到现有 `ADMIN_UUID` 用户，从而不增加第三个接入变量。

统一模式下，旧 Basic/Bearer/API token 只作为机器接口兼容入口，不得继续放行网页首页。网页导航必须由主站会话或 handoff 完成。

## 7. 前端结构标准

视觉参考不是配色表，而是本机原始项目 `octopus-kaogong-workbench` 的信息架构与交互语言。

桌面端必须包含：

- 浮动三栏应用壳：左侧导航、中心业务区、右侧详情/状态区。
- 中心顶部操作区。
- 2 至 4 个流体指标卡，内容使用真实业务状态。
- 卡片化主工作区；业务表格、配置表单和操作区嵌入其中。
- 亮色、暗色与 accent 切换，遵循主站母版 token。

子项目可按业务裁剪右栏或指标数量，但不能退回“顶部大横幅 + 横向 tabs + 若干旧卡片”的原页面结构。

圆角、材质、间距和响应式以 `design-system/styles.css` 为准。原始参考包含 14 至 28px 的层级圆角，不得另写“所有卡片不超过 8px”之类相冲突的规则。

业务映射：

- 住宅 IP 管理侧栏：代理切换、节点状态、出口列表、系统设置。
- VPS 和订阅管理侧栏：我的订阅、节点编排、分组管理、用户管理。

后端 API 和路由保持不变；前端调用现有接口，不为视觉改造重写业务协议。

## 8. 主站打开方式与嵌入协议

### 8.1 移动端

手机端主站保持正常首页，不进入嵌入窗口。用户点击接入项目时，在**当前标签页**直接导航到：

```text
<子项目 URL>?from=workbench&theme=<dark|light>&accent=<accent>
```

子站可据此显示返回主站入口。不得使用 iframe，也不得强制新开标签页。

### 8.2 桌面端

主站桌面端通过 embed handoff 加载 `<子项目 URL>?embed=1&theme=<dark|light>&accent=<accent>`。子站初始化：

```js
const params = new URLSearchParams(location.search);
if (params.get('embed') === '1') document.body.dataset.embed = '1';
if (params.get('from') === 'workbench') document.body.dataset.fromWorkbench = '1';
```

`body[data-embed]`：

- 隐藏子站自己的外层侧栏、顶栏和页脚。
- 保留中心业务工作区，撑满 iframe。
- 不隐藏业务操作、错误反馈或当前用户状态。
- 不读取主站 DOM，不 frame-busting。
- 若隐藏外层侧栏会导致业务页面不可达，必须提供紧凑的嵌入态导航。例如订阅项目至少保留“编排工作区 / 我的订阅”，管理员还应能进入“用户管理”。
- 已有持久化业务结果时应恢复到可查看状态；不得要求用户再次执行“保存”才能进入已经存在的订阅。

`from=workbench` 用于移动端独立打开，页面显示返回工作台按钮，并固定返回主站 `/workbench`，不得返回门户首页。顶层打开必须在点击时重新读取当前已解析的 `theme=dark|light` 与当前 `accent`，不能复用打开 iframe 时缓存的 URL。子站在首屏渲染前应用；这次皮肤只负责本次启动，不改变独立访问时的本地偏好。若子站已有持久化业务结果，移动端也应直接恢复到对应结果视图，例如订阅项目已有订阅时直接进入“我的订阅”。

网站导航在桌面端和移动端都使用新标签页或窗口直接打开，不进入 iframe，不请求 handoff，不写统一会话，也不参与预加载。目标网站无需识别 `theme`、`accent`、`embed` 或 `from=workbench`；主站不得尝试修改第三方网站的布局、主题或鉴权行为。

### 8.3 加载与 ready

主站在 iframe 鉴权回调、重定向和业务页面初始化期间显示与当前主题一致的不透明加载层。iframe 的 `load` 事件可能来自中间回调页，**不能**作为加载完成信号。

子站完成首屏主题应用和业务壳初始化后发送：

```js
window.parent.postMessage(
  { source: 'kypher-embed', type: 'ready' },
  'https://www.kypher72.indevs.in'
);
```

可选消息：`title`、`exit`。发送和接收均须精确校验 origin，禁止 `targetOrigin='*'`。

主站只在收到当前 iframe 的合法 `ready` 后关闭加载层。

### 8.3.1 可选预加载

接入项目可以在工作台创建或编辑时选择“提前加载子站”，对应保存字段 `preload: true`。主站不得把跨域 HTML、脚本或样式直接读取后注入另一个 iframe；标准实现是创建隐藏的同源 iframe 容器并使用正常 embed handoff，让浏览器提前完成子站资源、分区会话和业务壳初始化。收到该子站合法 `ready` 后标记为可复用，用户真正打开时移动同一个 iframe 到可见窗口。

预加载是性能优化，不改变鉴权协议。主站应限制数量和并发，优先使用 `requestIdleCallback`，仅使用 `transform`、`opacity` 等不会触发布局的过渡。移动端、`navigator.connection.saveData`、页面隐藏或 `prefers-reduced-motion` 场景应降低或跳过预加载。退出主站时必须清理所有子站会话；未启用预加载的项目不得改变当前按需 handoff 流程。

### 8.4 主题同步

主题同步分为首屏与实时两步：

1. 主站在签发 embed handoff 前把已解析主题写入查询参数：`theme=dark|light`。
2. 子站在 `<body>` 渲染前读取该参数并应用，优先级高于子站自己的 localStorage，避免白屏或主题闪烁。
3. 主站主题变化后发送：

```js
iframe.contentWindow.postMessage(
  { source: 'kypher-embed', type: 'theme', theme: 'dark', accent: 'ocean' },
  childOrigin
);
```

4. 子站仅接受来自 `AUTH_MASTER_ORIGIN` 的合法 `dark|light` 和允许的 accent 值，立即更新当前页面。
5. 子站从主站顶层打开时使用 URL 中的皮肤完成首屏匹配；没有参数的独立访问继续使用自己的本地偏好。

## 9. 设计系统同步

- 主站 `design-system/` 是母版。
- 子项目保存拷贝，可按构建方式拆分，但 token、主题存储 key、基础组件行为保持兼容。
- 同步时记录母版 commit，便于追踪差异。
- 子项目运行时不通过 `<link>` 或 `<script>` 跨域引用主站文件，避免主站故障拖垮独立站。
- 业务专属样式放在子项目层，不反向污染母版。

## 11. Cloudflare 项目改造成本

符合常规 Workers/Pages 结构的项目应能按本标准快速接入，核心工作固定为：

- 复制并接入统一鉴权模块，保留原鉴权作为独立站回退。
- 增加 handoff 回调、会话校验、统一退出与安全回跳路由。
- 前端识别 `embed`、`from=workbench`、`theme`，实现 `ready` 和主题消息。
- 管理员全局项目在 `apps.json` 注册；个人项目也可直接在用户工作台添加并获得独立密钥。
- 按验收清单验证统一模式和独立模式。

这套接入不要求统一域名，也不要求重写业务 API。已有鉴权模型特殊、用户映射复杂或前端没有清晰导航边界的旧项目，仍可能需要一个薄适配层；除此之外不应为每个 Cloudflare 子项目重新设计一套登录与门户协议。
